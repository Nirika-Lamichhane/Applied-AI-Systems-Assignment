# Production-Grade RAG AI Assistant

This assignment combines a **Retrieval-Augmented Generation (RAG)** pipeline, **dynamic tool calling**, **fine-grained LLM hyperparameter controls**, and **enterprise-grade reliability features** such as rate limiting, retry handling, and graceful degradation.

The application is exposed through a **FastAPI backend**, served with **Uvicorn**, and can be fully orchestrated using **Docker and Docker Compose**.

## Key Features

### 1. Advanced RAG Pipeline

The application implements a local **Retrieval-Augmented Generation** pipeline using ChromaDB.

Key capabilities include:

* Efficient document chunking
* Local vector storage using ChromaDB
* Semantic retrieval of relevant document chunks
* Automatic context injection into user prompts
* Context-aware responses generated by the Gemini model

The local corpus is provided through:

```text
backend/sample_doc.txt
```

---

### 2. Dynamic Tool Calling

The `/chat` endpoint supports conditional tool execution through the `use_tool` parameter.

```json
{
  "use_tool": true
}
```

When enabled, the backend executes a custom local tool alongside the RAG pipeline and returns the resulting output as structured metadata.

This allows the assistant to combine:

```text
User Prompt
     │
     ├──> RAG Retrieval
     │
     ├──> LLM Generation
     │
     └──> Optional Tool Execution
```

---

### 3. Prompt Engineering & Hyperparameter Control

The API provides runtime controls for important LLM generation parameters.

Supported parameters include:

* `temperature`
* `top_p`

Example:

```json
{
  "temperature": 0.3,
  "top_p": 1.0
}
```

These parameters are reflected in the structured JSON response metadata, making it easier to inspect and experiment with model behavior.

---

### 4. Production Reliability

The backend includes multiple resilience mechanisms designed to improve reliability.

#### Rate Limiting

Requests are limited to:

```text
10 requests per minute
```

Exceeding the configured limit results in:

```text
HTTP 429 Too Many Requests
```

Rate limiting is implemented using **SlowAPI**.

#### Retry Handling

Transient failures are handled using **Tenacity**, allowing selected operations to retry automatically when appropriate.

#### Graceful Degradation

If the Gemini API cannot be accessed because of issues such as:

* Network failures
* Missing API credentials
* External API availability problems

the application can fall back to deterministic outputs rather than completely failing the request.

This ensures that the API remains responsive even when external dependencies are unavailable.

                     │

## ONNX Optimization Justification

ONNX (Open Neural Network Exchange) was omitted from this implementation for architectural and operational reasons:

* **Cloud-Managed LLM Architecture:** Core text generation and reasoning are delegated to a managed cloud provider (`gemini-3.6-flash`) via the official Google GenAI SDK. Because model weights are hosted and served remotely by the provider rather than locally on the application server, there are no local neural network weight files to export, convert, or execute through an ONNX runtime.
* **Vector Store Separation:** The RAG pipeline relies on ChromaDB for local vector embeddings and retrieval. ChromaDB manages its own optimized embedded persistence layer, rendering deep learning model conversion formats unnecessary for similarity search.
* **Focus on Application-Layer Resilience:** Production engineering requirements (Task 2) focus on application-layer reliability such as rate limiting (`slowapi`), retry policies (`tenacity`), fallback wrappers, and tool routing—rather than on-device hardware acceleration or local model quantization.
